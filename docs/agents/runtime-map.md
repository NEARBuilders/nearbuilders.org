# Runtime map — who owns which screen, and who serves what

This app is a composed runtime: it may extend the published platform
(`extends: bos://…`) and override only what it changes. Some code is in this
repo; some is a remote Module Federation bundle inherited through `extends`.
The **facts** about that split are generated; the **conventions** are here.

Companions — the three docs form a navigation system:

- [`how-it-fits.md`](how-it-fits.md) — the drawn tour: authored → published →
  resolved → served; mounts, core-wins, shadows
- **this page** — the generated facts: who owns what, who serves what
- [`change-placement.md`](change-placement.md) — what to do about it: where a
  change lands and how it goes upstream

## Generated artifacts (never hand-edit)

| Artifact | What it is |
|---|---|
| `.bos/generated/runtime-map.json` | Full inventory: ui sources, **backends** (host, api, auth server, plugin backends — remote api/auth/plugins carry the composed plugin version + contract hash; the host ships no manifest asset and is inventoried source-level only), mounts, every composed route with its owner and full path, shadowed claims, unresolved sources |
| `ui/src/lib/runtime-map.gen.ts` | Typed view: `REMOTE_ROUTES`, `RemotePath`, `RUNTIME_SOURCES`, `RUNTIME_BACKENDS`, `RUNTIME_MOUNTS`, `SHADOWED_ROUTES`, `UNRESOLVED_SOURCES` |

Both are gitignored and regenerated by `bos types gen` (so also by
`pnpm run typecheck`, `bos dev`, and `bos build`).

The map is a **static model** of `constructTree` (the composition engine in
`every-plugin/ui/manifest`) — a framework test runs the real engine over the
same manifests and diffs the full-path sets, so the model cannot silently
drift from the engine. If you suspect the map lies, run typecheck; a red
parity test means the model needs updating, not that your app is broken.

Remote route manifests are served at `<ui.production>/manifest.gen.json` —
e.g.
`https://cdn.everything.dev/bundles/dev.everything.near/everything.dev/auth-ui/manifest.gen.json`.
They are **not** the plugin manifest (`plugin.manifest.json`, which the
backend inventory reads for versions/contract hashes) and not derivable from
the MF `entry`.

**Loud by default.** In `bos types gen`, an unresolvable remote manifest fails
the run — an upstream route rename breaks typecheck instead of silently
shrinking the map. Dev/build/train boots degrade to a warning (a flaky remote
must not block a boot; the runtime load fails loudly on its own). For offline
work, set `BOS_MAP_ALLOW_UNRESOLVED=1` (the map is still written, with the
unresolved sources listed).

## Investigation workflows — the agent's quick lookups

**"Who owns `/settings`?"** — grep the map, don't reverse-engineer
`constructTree` or grep `node_modules`:

```sh
jq '.routes[] | select(.fullPath == "/settings")' .bos/generated/runtime-map.json
# → { "owner": "auth", "mount": "authenticated", ... }
```

The TS surface is the typed version: `REMOTE_ROUTES` lists every non-core
route with `path`, `owner`, and `mount`.

**"Did my change just shadow a plugin route (or get shadowed)?"** —
`SHADOWED_ROUTES` (and `.shadowed` in the JSON). Core ui wins claims; a
shadowed entry names the loser and the reason. If your plugin route vanished,
it is here — not deleted, shadowed.

**"Which auth-plugin version am I actually composing?"** — the backend
inventory:

```sh
jq '.backends[] | select(.key == "auth")' .bos/generated/runtime-map.json
# → { "source": "remote", "pluginVersion": "2.0.0-rc.8", "contractSha256": "…", "location": "https://cdn…/auth/" }
```

A mismatch between `pluginVersion` and your `platform:` pin is a drift alarm.

**"Where does this change land?"** — the map gives the owner; the owner gives
the repo:

- owner is `ui` (core) or a **local** plugin/backend → this repo
- owner is a **remote** source (e.g. `auth`) → upstream
  (`github.com/NEARBuilders/everything-dev`, `plugins/auth/`), then arrive
  here via `bos upgrade` — hand it to
  [`change-placement.md`](change-placement.md) for the full decision tree
  (bug / missing capability / pattern improvement)

**"Is this app's bug local or upstream?"** — two cheap classifiers before any
debugging: the map's `owner` for the failing path (code living in the `auth`
source is not debugged here), and the resolved-config comparison in
[`how-it-fits.md`](how-it-fits.md) (which slots are local overrides vs
inherited).

## Sources and backends in this runtime

The map's `sources` section lists every **ui** source (key, kind, local or
remote, where it lives). The `backends` section lists every **serving** slot:
`host` (source-level only — the host ships no manifest asset), `api`, `auth`
(the Better-Auth + NEAR SIWN server), and each plugin backend. For remote
backends, the entry records the composed bundle's `pluginVersion` and
`contractSha256` from its published `plugin.manifest.json`.

## When the map is missing

`.bos/generated/runtime-map.json` absent means `bos types gen` has not run
since checkout (or every source failed to resolve). Run `pnpm run types:gen`.
The map's absence never blocks a boot — only `bos types gen` (strict mode)
fails on an incomplete map.
